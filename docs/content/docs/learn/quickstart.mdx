Fuse has two parts: the **CLI** on your laptop, and a **stack** (orchestrator,
host agent, microVMs) that runs wherever there is KVM. Pick where the stack runs:

| | Run it locally | Run it on a KVM server |
| --- | --- | --- |
| Where | Your laptop | A Linux box you can SSH into |
| Needs | Linux with `/dev/kvm`, or macOS 15+ on M3 or later | Linux x86_64 with `/dev/kvm` and `sudo` |
| Setup | `fuse local up` | `sudo ./scripts/fc-agent.sh bootstrap` |
| Good for | Trying Fuse, developing a Fusefile | Real workloads, a team, always-on |

Both run the same binaries, so a Fusefile that works on one works on the other.

## 1. Install the CLI

```bash
brew install --cask folsomintel/fuse/fuse
```

Or, without Homebrew (macOS and Linux):

```bash
curl -fsSL https://raw.githubusercontent.com/folsomintel/fuse/main/ops/install-fuse.sh | bash
```

Check it with `fuse --version`.

:::warning[Always use the full cask name]
Homebrew has an unrelated cask called `fuse`. Always install and upgrade with
`folsomintel/fuse/fuse`, never a bare `fuse`. More install options are under
[Installing the CLI](#installing-the-cli) below.
:::

## 2. Start the stack

Do **one** of these.

### Option A: locally

```bash
fuse local up
```

The first run downloads Firecracker, a kernel, a base rootfs and the fuse
binaries into `~/.fuse/local/` (on macOS it also boots a small Linux appliance
VM, so install [vfkit](https://github.com/crc-org/vfkit) first with
`brew install vfkit`). It then connects the CLI to a context named `local` and
registers your machine as a host. Later runs take seconds.

Stop it with `fuse local down`. See [Local development](/docs/guides/local-development)
for requirements and troubleshooting.

### Option B: on a KVM server

On the server, check that KVM is there, then clone the repo and run bootstrap:

```bash
ls -l /dev/kvm   # must exist, or the box cannot run microVMs

git clone https://github.com/folsomintel/fuse && cd fuse/host-agent/firecracker
sudo ./scripts/fc-agent.sh bootstrap
```

`bootstrap` installs the host dependencies, Firecracker, the host agent, a local
Postgres and the orchestrator as systemd services, bakes the guest rootfs,
registers the box as host `local-fc`, and turns on a weekly auto-update. It is
safe to re-run. It ends by printing the line to run on your laptop:

```text
 fuse host ready
   orchestrator : http://203.0.113.10:8080
   token        : 3f9c...

   drive it from your laptop:
     fuse connect http://203.0.113.10:8080 --token 3f9c...
```

Open `8080/tcp` from your laptop to the server (or put it behind a TLS proxy or a
tailnet), then run that `fuse connect` line on your laptop.

:::note[No `/dev/kvm`?]
Ordinary cloud VMs do not expose KVM. Use bare metal (Hetzner dedicated,
Equinix, AWS `*.metal`) or an instance type with nested virtualization enabled.
See [Firecracker host setup](/docs/cloud/firecracker-host-setup) for the full
requirements and the step-by-step equivalent of `bootstrap`.
:::

## 3. Write a Fusefile

In any project directory, save this as `Fusefile`:

```yaml
version: 1

resources:
  cpus: 2
  memory: 2GB

run: echo "hello from $(hostname)" > hello.txt
```

That is the whole shape: how big the box is, and what to run on it. See
[Your first Fusefile](/docs/learn/first-fusefile) for what each line does, and
[Fusefile](/docs/concepts/fusefile) for every field. `fuse init` writes a fully
commented example with every field filled in, which is a good reference but
needs editing before it boots.

:::warning[`run` must terminate]
`run` executes while the environment is being created, so a command that never
returns (a foreground server, `sleep infinity`) fails the create. Background
anything long-lived, or declare it under `services`.
:::

## 4. Bring it up

```bash
fuse up
```

`up` creates an environment from the Fusefile and streams events until it is
`running`, then exits. If it ends up `failed`, `up` exits non-zero.

## 5. Use it

```bash
fuse environment list
fuse environment exec <id> -- cat /workspace/hello.txt
```

## Already have an orchestrator and host?

If you deployed the pieces yourself (see [Orchestrator deploy](/docs/cloud/orchestrator-deploy)
and [Firecracker host setup](/docs/cloud/firecracker-host-setup)), connect the CLI
and register the host in one guided pass instead of step 2:

```bash
fuse quickstart
```

It prompts for the orchestrator URL and token, then the host's ID, agent URL and
agent token. On a non-tty, run the two steps it wraps:

```bash
fuse connect https://orch.example.com --token "$ORCH_AUTH_TOKEN"
fuse host register prod-east-1 \
  --url http://10.0.0.5:8090 \
  --token "$FC_AGENT_TOKEN" \
  --max-vms 20
```

:::warning[Two different tokens]
`ORCH_AUTH_TOKEN` authenticates **you to the orchestrator**. `FC_AGENT_TOKEN` is
what the **orchestrator uses to reach the host**. They are not interchangeable,
and a mismatched agent token shows up as `http 401` on the first `fuse up`. See
[`fuse quickstart`](/reference/cli/quickstart) for every prompt.
:::

## Installing the CLI

The install script verifies the release archive against its `checksums.txt` and
installs to `/usr/local/bin` (or `~/.local/bin` when that is not writable).
`VERSION=vX.Y.Z` pins a release and `FUSE_INSTALL_DIR=/path` picks the target.
You can also download the `fuse-cli_*` archive for your platform from the
[latest release](https://github.com/folsomintel/fuse/releases/latest).

If macOS refuses to open a binary you downloaded through a browser, clear the
quarantine attribute:

```bash
xattr -dr com.apple.quarantine ./fuse
```

Upgrade a Homebrew install with `brew upgrade --cask folsomintel/fuse/fuse`.
