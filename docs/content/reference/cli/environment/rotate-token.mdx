```bash
fuse environment rotate-token <id>
```

Alias: `rotate`. No flags beyond the globals. Generates fresh TLS credentials
and an auth token for the environment, writes them to the guest's credential
files, and persists the orchestrator's new encrypted copy. The environment
keeps running throughout.

```bash
fuse environment rotate-token fuse-abc123
# rotated token for environment "fuse-abc123"
```

The running agent picks the new credentials up in place: the orchestrator
sends `fused` a `SIGHUP` after writing the files, and the old token is refused
from the next request. A guest whose `fused` predates the reload handler exits
on the signal and is restarted onto the new files.

## Errors

Rotation only works on a `running` environment. That precondition does not wrap
a sentinel error, so it surfaces as HTTP 500 rather than a 4xx.

:::warning[Known limitation]
A 500 from `rotate-token` almost always means that precondition rather than a
real server fault. It is a permanent property of the request, not a transient
failure, so the status should be a 4xx. Match on the error message
(`token rotation requires running`) rather than the status until this is
fixed.
:::
