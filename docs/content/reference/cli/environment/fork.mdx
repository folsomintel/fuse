```bash
fuse environment fork <id> [flags]
```

Creates one or more new environments seeded from one snapshot of an existing
one.

## Flags

| Flag | Purpose |
| --- | --- |
| `--reuse-snapshot` | Reuse an existing snapshot ID instead of taking a new one. |
| `--comment` | Comment recorded on the seed snapshot the fork creates. |
| `--live` | Resume every child from a live snapshot's memory image instead of cold-booting its disk. |
| `--count` | How many children to fork from the one seed (default 1, at most 1000). |

## Behavior

With no `--reuse-snapshot`, the server takes a fresh snapshot of `<id>` first,
then forks from it. With `--reuse-snapshot`, it skips that step and forks
directly from the named snapshot instead, which also makes `--comment` a no-op,
there is no new snapshot for it to be recorded on.

```bash
fuse environment fork fuse-abc123 --comment "branch for experiment"
# forked environment "fuse-abc123" into fuse-xyz789
```

```bash
fuse environment fork fuse-abc123 --reuse-snapshot snap-1
```

With `--count N` the seed is taken once and N children are forked from it. One
child prints its detail view; several print a table, one row per child. With
`-o json` the output is always a JSON list of environments, even for one
child. Each child is its own fork: if one fails, the others keep running and the
command exits non-zero with a message naming the children that did fork.

With `--live` the seed is a live snapshot (or `--reuse-snapshot` must name a
live one), and each child resumes from its memory with its processes intact. A
live child cannot resume on its source's own host yet, so it always lands on
another host of the same backend, CPU model and Firecracker build. Without
`--live`, a fork of a live snapshot is refused.

```bash
fuse environment fork fuse-abc123 --live --count 3
```

Fork is unavailable wherever snapshotting is, GPU/QEMU-backed environments
cannot be forked. See [Snapshots](/docs/concepts/snapshots) and
[Providers](/docs/concepts/providers).

## Errors

| Status | Code | When |
| --- | --- | --- |
| 400 | `invalid_argument` | `--count` is below 1 or above 1000 (the CLI refuses below 1 before sending). |
| 404 | `not_found` | `--reuse-snapshot` names a snapshot that belongs to a different environment. |
| 409 | `conflict` | The reused snapshot is not in the `ready` state, its kind does not match `--live`, the source environment holds a GPU passthrough device, or a `--live` fork has no host other than the source's to resume on. |
| 503 | `unavailable` | No host has room for a child. |
| 500 | `internal` | The source environment is not `running`. |

The 404 reads confusingly when the snapshot plainly exists: a snapshot of
another environment is rejected as not-found rather than as a mismatch.

:::warning[Known limitation]
The not-running rejection still returns HTTP 500 because that path does not
wrap a sentinel error. It is a permanent property of the request rather than a
server fault, so the status should be a 4xx. Match on the error message
(`fork requires running`) rather than the status until this is fixed.
:::
